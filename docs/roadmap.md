## 多源感知与用户状态判断（2026-11-06 讨论）

### 用户明确提出的方向

- 尽快、尽可能多地收集与滑雪状态相关的信息，例如运动传感器、陀螺仪、电量、GPS 等，综合判断用户当前状态，作为后续功能设计的总原则。
- 硬件目标为 **iPhone 15 及以上**，不支持更老机型。具体型号覆盖（含后续不同系列）、系统最低版本与限制方式待细化；这是产品方向，尚未修改现有兼容配置。
- 本轮只讨论并记录想法，不写代码。下列功能、技术方案与优先级均为建议，未批准实施，不分配变更编号。

### 建议的基础能力

建立统一的采集与状态判断层，向录制、评分、教练及安全功能提供结果，避免各功能重复采样。结果应包含时间、数据来源、数据质量与置信度；信号不足时允许输出“未知”，避免强行判断。

“尽快、尽可能多”具体如何落地仍待设计：在用户授权和功能使用范围内，按场景调整采样频率，平衡判断延迟、耗电、存储和后台限制。核心能力应遵循 [PRD 产品原则](PRD.md#2-产品原则)。现有实现及未接线功能见 [技术方案](architecture.md#并行--未接线的实现修改前先确认)。

### 候选信息来源

| 信息 | 预期用途 | 待核实或验证的边界 |
| --- | --- | --- |
| GPS 位置、速度、航向、精度、时间 | 判断移动、轨迹和数据可信度 | 航向在低速时可能不可靠；不同机型的定位能力需分别核验 |
| 加速度、陀螺仪、融合姿态 | 分析冲击、旋转、节奏和静止状态 | 手机运动不等于人体运动；携带位置与松动程度会影响结果 |
| 气压、相对高度、可用的绝对高度 | 辅助判断上升/下降、每趟落差和上下行切换 | 与 GPS 融合并校准，不能直接承诺替代 GPS 或提高坡度精度；气压变化和高度误差需处理 |
| 系统活动分类 | 辅助识别静止、步行、乘车 | 系统分类不能直接区分滑雪与缆车 |
| 电量、充电状态、低电量模式、热状态 | 调节采样、评估续航、提醒充电 | 热状态不提供环境温度；掉电快不能直接归因于低温 |
| 网络可用性、请求成功情况 | 离线缓存、提示消息发送状态 | 无法保证预测即将失联，也不能保证求救消息送达 |
| 雪场天气、风速、预报 | 提供环境背景与保暖提醒 | 天气服务数据不是用户所在位置的实时实测 |
| 可选 Apple Watch 心率、活动数据 | 辅助观察运动负荷和休息恢复 | 需核验设备、权限、实时性与后台能力；不能假设 HRV、血氧均持续可用 |
| 可选兼容耳机的头部运动数据 | 探索头部转动与身体运动的关联 | 依赖耳机型号及佩戴情况，不作为核心能力前提 |

### 希望识别的状态

- **运动状态**：滑行、缆车上行、步行、静止休息，以及状态切换。
- **场景线索**：可能进入室内、可能离开雪场；GPS 变差或长时间静止只能作为线索，不能单独确认。
- **安全事件**：疑似摔倒、摔倒后长时间未活动；应提供确认/取消流程。
- **负荷趋势**：动作节奏变化、休息后恢复情况、可能需要休息；属于待验证提示，不作为医学诊断。
- **设备与环境状态**：定位不可靠、低电量、网络不可用，以及天气风险背景。

上述均为推断目标，尚无经过实测的分类规则、阈值或准确率。上一轮提到的缆车速度范围等只作举例，不作为产品规则。

### 候选功能与建议顺序

| 建议顺序 | 功能 | 用户收益与设计方向 |
| --- | --- | --- |
| 优先评估 | 自动分趟与缆车识别 | 融合升降趋势、速度和运动信号，分开滑行、上行、休息；每趟独立统计，减少非滑行时段对均速和评分的干扰 |
| 优先评估 | 高度融合与落差统计 | 结合气压和 GPS，验证能否改善落差、上下行判断；坡度推算另行验证 |
| 优先评估 | 跌倒检测升级 | 融合冲击、旋转、后续活动情况和速度变化，验证误报/漏报；可用时参考 Watch，但不能要求双设备均确认才处理 |
| 基础配套 | 电量守护与自适应采样 | 根据运动状态、电量及数据质量调节采样，保存最新位置与时间；续航预估需实测校准 |
| 后续评估 | 转弯与节奏分析 | 探索转弯计数、左右对称性和节奏稳定度，为评分与教练提供更多依据；先验证手机携带位置的影响 |
| 后续评估 | 倾斜与动作分析 | 在固定携带位置、完成校准的前提下探索姿态分析；不能直接把手机角度当成人体倾角或雪板立刃角 |
| 后续评估 | 休息与疲劳趋势提醒 | 结合连续滑行时间、节奏变化和可选心率给出休息提示，避免直接断言用户疲劳 |
| 后续评估 | 天气与保暖提醒 | 结合天气、风速、户外活动时长给出提示；不判断实际体温或失温 |
| 后续评估 | 失联准备与位置留存 | 离线保留最近位置、时间和待发消息，恢复网络后重试；对外发送及紧急联系人授权流程待设计 |
| 后续评估 | 自动开始/暂停 | 根据到达雪场、下滑、长时间静止等线索提示或切换记录状态；提示式与全自动方式待决定 |

### 待决事项与验证入口

- [ ] 明确首批功能与验收指标：识别延迟、分趟准确率、跌倒误报/漏报、每小时耗电等。
- [ ] 确认支持的具体机型、系统版本与能力降级策略；iPhone 15 及以上并不意味着全部传感器能力一致。
- [ ] 确认手机推荐携带位置、是否要求校准，以及 Watch/耳机缺席时的行为。
- [ ] 核验传感器 API、权限、后台/锁屏采样和耗电限制；不以模拟器验证代替真机雪场数据。
- [ ] 确认原始数据与状态结果的保存范围、时长、导出/删除方式，以及联系人消息授权。
- [ ] 设计真机采集与标注方案，覆盖不同机型、口袋位置、滑行/缆车/步行、急停、手机掉落等场景；先离线验证分类，再决定提醒和自动化行为。
